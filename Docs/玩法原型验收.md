# 天气屋玩法原型

## 已完成的独立阶段

- 程序化 UI 控件：动物气泡、玩家气泡、三点、缺口圆圈关闭、圆角取景框、双圆快门、小圆点。菜单 `Weather House/Review Procedural UI Controls` 生成预览与可编辑 Canvas 预制体；控件可调整尺寸、颜色、线宽和轮廓波动。
- 语言手账状态：观察记录、自由猜义、照片按字符筛选、跨动物语义确认，以及 JSON 保存和恢复。菜单 `Weather House/Validate Gameplay State` 执行 13 项检查。

猜义与拍照均不会自动确认词义。只有后续不同动物的回答判定，才允许确认当前语句中被正确理解的字符；天气任务完成与语义确认分别记录。

## 场景绑定

场景中新增 5 个局部天气区域、7 只程序化占位动物。场景层级 `06 观察、天气与动物` 可直接编辑天气半径、动物位置、字语和请求含义。安装器在现有地图上添加玩法，不改地形；重新生成地图时也会生成玩法对象。

`E` 中文回应，`C` 相机，空格或快门拍摄，`J` 手账，`Esc` 返回，`1/2/3` 雨/晴/风。手账与输入框打开时阻止角色操作；拍照模式保留看向和移动并阻止空格跳跃。观察需要在 10 米内看向动物且视线无遮挡。

动态照片记录 3 秒、6 帧/秒、512×288 的实际世界画面，逐帧保存，字语快照跟随照片保留；默认封面静止，展开后手动播放。原型不含音频、视频压缩或云同步。照片文件与语言手账保存在 Unity 的应用持久目录中。

24 个原字形直接来自已有 v03 字库。当前几个生活区域只用其中一部分，未遇见的字仍保持未知。临时请求覆盖庭院晾松果、湖畔浅洼补雨、高台起风、林中晾布；自由探索，四处天气请求都完成时出现本轮结束提示。

真实 AI 判定尚待用户提供服务配置。缺失配置或请求失败时不确认词义，不使用本地关键词规则冒充模型判定。客户端离线检查验证结构和证据 ID 边界，不能证明实际模型的语义质量。

原型中未定稿的湖畔、高台请求使用可编辑的临时内容，不作为最终关卡策划。AI 接口使用 OpenAI 兼容服务；等提供 Base URL、模型及本地 Key 后才进行真实联调。
