# 羊群水岸生活样板

本批用 10 只羊验证跨区活动、能力不同的临时分队、过桥排队、会合和稀疏交流。实现位于 `Assets/Game/World/Wildlife/Journey`。独立样板已完成运行验收；水岸主地图已通过构建与双向路线验收，转交其中 10 只羊给新行为，保留其余 70 只动物，主地图 Play 检查仍在继续。

## 已确认的设计

- 群体在合适区域内呈自然、不规则的分布，个体有间距；共享活动目的地，各自保留体型、步速、迈步相位和启停差异。
- 可以跨区活动。根据水深、连续游泳距离、岸坡和真实桥面判断通路；游泳时身体部分入水、头部保持在水面上方，不能沿河底潜行。
- 同群允许临时分队：有的游水，有的绕桥，到目的地重新会合。先到者可以吃草和等待；窄桥上的羊依次通过。
- 聊天有明确的说话者和听者，控制频率并轮换参与者。部分表达提供动物语线索，其余保留简单生活交流。
- 肢体互动以自然动作和少量童话感为方向，目标包括嗅闻、碰鼻、蹭身、回头招呼。当前先实现靠近、朝向对方和轻量头部动作，完整动作素材仍需继续完善。

## 分层与复用

| 部分 | 当前职责 | 接入其他场景时需要提供 |
| --- | --- | --- |
| `JourneyNavigation` | 对候选路线逐段检查地面、水、坡度、身体宽度和障碍；以行走、涉水、游泳的代价搜索路线 | 地形或地面 Collider、水域范围、桥面 Collider、候选节点和连接 |
| `JourneyScatter` | 在有平滑噪声边缘的平面区域内按最小间距撒点；种子可复现，空间不足时整体失败 | 中心、半径、间距、数量、种子和可选的点位筛选 |
| `JourneyHerd` | 活动评分、独立目的点与节奏、分队行进、桥口预约、受阻记忆和会合 | 成员、能力参数、草地等活动区域 |
| `JourneyCrowdPath` | 仅在陆地受同伴阻挡时建立局部可见图，寻找保留身体间距的短绕行 | 附近身体范围与真实地面通行检查；水中和桥上仍遵循原通行规则 |
| `JourneySocial` | 双方预约、参与者及组合冷却、轮换、可见性、已有字库气泡和观察记录 | 观察相机、遮挡层、可参与的个体 |
| `JourneyLabControls` | 样板的观察、暂停、换区、封桥、拍照与诊断 | 上述组件和桥口障碍引用 |

路线图只描述“可以尝试往哪里走”。桥链接必须有真实桥面支撑；下水路线还要检查出口和连续游泳距离。途中移动使用 `TryStep` 检查脚下连续性，不能因为目标点可站立就跳上高岸或上方桥面。

当前群体与局部避让按小规模样板实现；本批没有给 80 只动物的主地图作性能验收。

## 真实入口与操作

已生成场景 `Assets/Scenes/Experimental/WildlifeJourneyLab.unity`，打开后可进入 Play。重建使用菜单 `Weather House / Wildlife Journey / Build Independent Sheep Lab`，对应 `JourneyLabBuilder.Build()`；生成器将场景保存后关闭，再手动打开。

生成器在 Preview Scene 内构造，用短暂的 Additive 场景保存。它不会保存当前用户场景；遇到未命名场景会在写入前提示先保存或关闭。若样板本身已打开，先关闭再重建，以免覆盖其中尚未保存的调整。生成资源位于 `Journey/Generated`，现有羊预制体只被实例化，原资源不改。

| 操作 | 效果 |
| --- | --- |
| 鼠标右键、滚轮、WASD | 转动、缩放、平移观察相机 |
| `Space` / 暂停按钮 | 暂停或继续本样板的行为与动画 |
| `R` / 前往另一片草地 | 空闲时发起另一岸的旅程；旅途中等待会合 |
| `B` / 改变桥口 | 在允许的时机启用或撤除桥口障碍；桥上还有羊时先等它们通过 |
| `Tab` | 显示个体判断、会合及改路次数，并调整交流间隔、会合后停留时间 |
| `C` / 记录交流 | 当前能看清双方交流时，保存照片和原始交流语境 |

照片输出到工程根目录 `JourneyReview/Photos`，包含 PNG 和同名 JSON。JSON 保留说话者、听者、字语、双方位置与相机信息。当前入口使用样板自己的记录文件，尚未接入旧相册界面。

## 在 Inspector 中调整

选中 `03 Sheep herd` 的 `JourneyHerd`。`members` 每项的 `id` 必须唯一；`root` 是位于脚底的世界移动根，`visualRoot` 保留模型对齐偏移，`animator` 与 `clips` 指向同一套绑定。当前羊的头骨为 `Head`，划腿骨为 `UpperArm.L`、`UpperArm.R`、`Thigh.L`、`Thigh.R`。

替换羊时，在样板中实例化新的模型并重新填写这些引用；只移除克隆上的旧行为控制器，避免两个控制器同时驱动同一只动物。不同骨架需要重新绑定头、四肢及动画，不能沿用羊的骨骼名称。`profile` 可分别调整 `canSwim`、`wadeDepth`、`maxSwimDistance`、`walkSpeed`、`swimSpeed`、`waterAversion` 和 `bodyRadius`。成员的 `bodyLength` 表示纵向身体长度，`profile.bodyRadius` 表示横向半宽；体型变化后同时检查这两个尺寸与 `waterlineHeight` 浮水高度。`JourneyHerdChecks.DescribeBodySizes()` 用项目既有的 `BakeMesh(true)` 方式采样真实宽、高、长及脚底偏移，并要求尺寸处于 0.1–5 米，防止 FBX 缩放导致百倍测量错误通过检查。

`sites` 设置活动区域的中心、半径、食物吸引力 `forage` 和休息吸引力 `rest`。`autoAdvance` 决定是否自动换区，`minimumStay` 控制会合后的停留，`rendezvousTimeout` 控制受阻后的会合处理。运行时调整用于试验；要保留参数，在退出 Play 后写回场景。

替换地形时，选中 `02 Surface-aware navigation`：

1. Unity Terrain 填入 `terrain`；网格地面使用 MeshCollider，并让 `groundMask` 包含地面和桥面。样板使用第 8 层为地面、第 9 层为障碍，未修改项目的层名称。
2. 有 `WorldWaterSurface` 时填写 `worldWaterSurface`，由其提供权威水域边界与水位；否则使用 `waterAreas.bounds` 的 XZ 范围和 `surfaceHeight`。水面渲染网格不要加实体地面 Collider。
3. `bridges` 填唯一正数 `id` 与实际桥面 Collider，桥端需要连续、可走的岸坡。`obstacleMask` 包含真实阻挡物，避免把整片地面误设为障碍。
4. `nodes` 放在草地、岸边和桥端；`links.from/to` 填节点数组下标。桥链接的 `bridgeId` 与桥面注册一致。活动区域需在节点的可连接距离内。
5. 场景编辑完成后重新进入 Play；运行时代码改变通路时调用 `Physics.SyncTransforms()` 和 `navigation.Rebuild()`。自定义世界高度接口可以接入 `surfaceSampler`，它是运行时委托，不是 Inspector 字段。

## 自动验证

检查工具位于 `Assets/Game/World/Wildlife/Journey/Editor`：`JourneyScatterChecks`、`JourneyNavigationChecks`、`JourneyCrowdPathChecks`、`JourneyAvoidanceChecks`、`JourneyHerdChecks`、`JourneySocialChecks` 均提供 `RunLogicChecks()`，使用纯数据、独立对象或 Preview Scene。前五项菜单位于 `Weather House / Wildlife Journey`，交流检查位于 `Weather House / Journey / Check Social Logic`。`JourneyHerdChecks.RunSceneChecks()` 验证真实地面、桥面、羊绑定和尺度；`BatchTraceHerd()` 可在独立批处理工程输出逐成员轨迹，支持 `-journeyTraceLandBlocked` 受阻场景。

完整批处理只在独立验证工程运行。准备包含相关 Assets、Packages、ProjectSettings 及原 `.meta` 的独立副本，在其根目录创建空文件 `.wildlife-journey-validation`，再调用：

```powershell
$validationRoot = 'C:\验证工程\WeatherHouseJourneyValidation'
$unityEditor = 'C:\Program Files\Unity\Hub\Editor\2022.3.62f3c1\Editor\Unity.exe'
New-Item -ItemType File -Path (Join-Path $validationRoot '.wildlife-journey-validation') -Force | Out-Null
& $unityEditor -batchmode -nographics -projectPath $validationRoot `
  -executeMethod WeatherHouse.WildlifeJourney.Editor.JourneyLabBuilder.BatchBuildAndCheck `
  -quit -logFile (Join-Path $validationRoot 'Batch.log')
```

批处理入口要求 `Application.isBatchMode` 与上述标记同时成立。它仅在验证副本内把初始未命名场景保存为 `Generated/BatchBootstrap.unity`，再构建样板。正常 `Build()` 不执行这一步。报告写入验证工程的 `WildlifeJourneyReview/batch-checks.txt`，运行前覆写为带 UTC 时间的 `RUNNING`，结束时写 `PASS` 或 `FAIL`，避免误读上次结果。

交付报告 [JourneyReview/batch-checks.txt](../../JourneyReview/batch-checks.txt) 的真实 Unity 批处理全部通过：5 组撒点、14 组导航、5 组局部路径、4 组避让案例、完整群体与 6 组交流检查，以及真实场景检查。固定三羊案例中，移动者用时 9.05 秒、行走 7.77 米、保留最小中心距离 1.220 米；先到同伴围住后来者的案例在自然让路后用时 8.90 秒、行走 6.84 米抵达。漫游绕路和社交贴近后的安全退出也验证了持有路径实际执行、完成清理和继续活动。真实场景模拟 300 秒后全员会合。报告对应当次构建，后续源码修改仍需重跑。

Play 画面检查使用 `Editor/JourneyPlayReview.cs` 的 `JourneyPlayReview.Begin`，命令保持 `-batchmode`，去掉 `-quit` 和 `-nographics`。它需要真实图形设备，最新原始输出在独立验证工程的 `WildlifeJourneyReview/Play_20261023_182023_705`；本项目交付副本在 [JourneyReview/Play_20261024_022023](../../JourneyReview/Play_20261024_022023)。目录名采用不同时间标记，`summary.json` 保留原输出路径与 UTC 时间。

这轮真实 Play 记录了 146.756 秒模拟、4403 帧，完成往返两程、6 次可观察交流，出现 `hello` 和 `you`，4 只游泳、6 只走桥。返程为第 87.519–143.755 秒，共 56.236 秒；上一轮受同伴包围时为 110.648 秒。连续 1.2 秒泳姿采样共 12 帧，四条腿均有运动，头部最低高于水面 0.184 米；[完整周期 GIF](../../JourneyReview/Play_20261024_022023/游泳完整周期.gif)、同伴让路截图、`summary.json` 和含个体判断的 `trajectory.csv` 均已保留。

受阻者先尝试安全绕行；确实无路时，请附近一个已经抵达且未交流的同伴挪开最多 1.2 米。让路使用正常半速行走，逐段检查地面和身体间距，目标始终留在活动区。现有移动目标承担短暂承诺，避免多个请求反复改变同伴方向。社交贴近后可以单调增加距离退出，不能加深已有接触。

- 样板地形、河面和桥采用简洁自有几何与平色 URP 材质，便于观察通行判断；它们不是主地图美术成品。
