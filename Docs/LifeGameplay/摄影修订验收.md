# 摄影与 31 字修订验收

适用入口是 `Assets/Scenes/WeatherHouse_WatersideV2.unity`。依据为桌面 `拍照与文字玩法修订_20261026` 中的实现交接、26 条任务清单和 31 词覆盖核对。本页记录摄影模块的行为、检查入口和人工验收边界；整体运行结论由主任务报告汇总。

本修订覆盖原摄影规则。自由照片不要求动物、已知词、读过任务或 AI 理解；P01–P22 与 I01–I04 只发预设的 1–2 个词义。真实 AI 仍负责理解动物需求并接受帮助任务。旧原型保留的跨动物字义确认接口不再向正式 Life 模式发词。

作者验收表中的任务名称按当前 `LifePhotoTasks.cs` 的 `tokens` 与正式字库逐字对应，完整对照见[26 条实际任务清单](摄影任务清单.md)。例如 P01 为“狐狸”，P02 为“松鼠”，P04 为“草·湿”；原 CS `title` 中的“树根后的尾巴”“院边的回头”仍保留为历史场景设计标题，不用于报告命名。圆点表示词的分隔，不是额外验收条件。此对照供作者验收使用，游戏任务页继续显示原创动物语字形，不增加未解锁词的中文答案。此次不修改运行时源码，任务 ID、正文 token、奖励与匹配条件均保持原样。

## 保存和迁移边界

每次快门先同步写首张 `frame_000.png`，完整 Live 默认共 18 帧、6 FPS、512×288。照片完成后写独立元数据，再加入手账、按快照匹配奖励并写索引。照片 ID 是独立 GUID，帧加载只允许对应的 `MotionPhotos/<id>` 本地目录。

正常收相机、记录器禁用及 Gameplay 的退出回调调用 `FinishLiveCapture`，保留已完成的帧。可见话轮变化也保留首帧并停止追加帧。后续 Live 帧写入失败时保留成功帧，通过 `captureWarning` 记录中断；元数据独立文件写入失败时，仍尝试在手账索引保存完整快照，界面说明动态片段未完整保存。显式测试取消仍只清理该次临时目录。回放始终读取记录中的字序、参与者、锚点及世界快照；全局已知词的中文可以更新，照片中的历史事实不改写。
