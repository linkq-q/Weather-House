# 摄影世界快照与验收

依据桌面 `拍照与文字玩法修订_20261026/实现交接_含v04字形.txt`、`任务清单.json` 实现。原帮助仍需要近距交流、AI 理解与接取后的行动；摄影发词和 I01—I04 教学奖励独立于这条帮助流程。

## 代码与数据

- `Photography/LifePhotoSnapshot.cs` 定义照片的值快照、实体状态与公开情境，拷贝为深拷贝；不保存 Transform 引用。
- `LifePhotoTasks.cs` 保存批准的 22 条 P 任务和 4 条 I 任务的 ID、正文 token、奖励、操作、验收与恢复原文。
- `LifePhotoRules.Match(snapshot, history)` 为纯匹配器。不读取当前天气、动物、已知词或浏览顺序。同照可多命中；仅住处归属允许后来的公开历史补匹配旧照。其他感受／问候／道别只看快门快照携带的当时语境。
- `LifePhotoCapture` 取得实际相机的物体投影、可见几何遮挡、主体骨骼位置、正在显示的雨粒子、水面、材质状态、真实进食／睡眠与共享活动。全局雨、后台进食或单纯同框不会直接变成奖励。
- `PhotoSubjects.asset` 引用原地图 Fir 系列的 33 个共享 Mesh，按共享网格和 LOD 根识别实例；不按实例名称给树奖励。原 Unity Tree 组件也可成为树主体。
- `LifeWorld.PhotoContext` 在真实话轮显示后接收 `ObservePhotoConversation`。公开历史包含说话者、听者、位置锚点、原字形、说明与关联事件；主任务的 Notebook 负责持久化与回看。
- 同一话轮语境使用稳定 ID 更新当前记录，照片保留快门时的深拷贝。每帧只检查未完成互动队列，不再复制、遍历全部历史。已完成互动奖励保持幂等。
- 住处实体只读取该站点绑定的真实棚顶 Renderer 或明确放在该处的草垫；附近草束、水碗和其他装饰不能冒充住处。
- `openForPhotography` 只开放 E6a、E6b 及三条两步教学话轮；其余帮助前置条件保留，开放话轮本身不自动接帮助任务。

进食使用原羊群 forage 片段，约 6 秒。草束只消费一次，此后同一模型作为嘴边食物视觉保持，租约或动作结束后销毁，不再留作可重复拾取材料。嘴部锚点是正式 Head 权重下唇顶点 5492／5570 校准的局部点，由生产 `TryMouthPoint` 读取；不在运行时重读不保留 CPU 数据的原 Mesh，也不再按根朝前的头部邻域最远点选嘴。实际食物接触面只在本次活动中被声明为自身接触表面，无关前景仍会遮挡。

## 当前检查入口

`LifePhotoWorldChecks.Run(LifeSession)` 在主任务隔离存档 Play 中执行；不控制编辑器，不保存主场景。它调用纯规则检查，然后实际拍摄正式模型，写 `LifeGameplayReview/20261026/photo-flow/world-checks.json` 和对应 PNG。

`LifeWorldAsyncChecks` 在真实两只松鼠休息后调用 `CheckSharedRest`，在两只松鼠同时实际触水时调用 `CheckSharedDrinking`，在原羊真实进食保持约 5 秒后调用 `CheckEating`；分别写实际快照 JSON 与画面。动物始终使用原控制器，不为拍摄测试移动其 Transform；测试相机、玩家初始位置和不透明遮挡物属于声明的夹具。单只与共同饮水继续使用原实际蒙皮／口部接触阈值，不因摄影放宽。
