## 坐标和镜头约定

世界 `+x` 为东，`+z` 为北。设计坐标为 `x=1.8u-90`、`z=90-1.8v`。`yaw=0` 朝北、`90` 朝东；`pitch` 为向下角度。镜头位置使用：

```csharp
rotation = Quaternion.Euler(pitch, yaw, 0);
camera.position = target + rotation * Vector3.back * distance;
```

地面向量在屏幕水平轴上的投影为 `dx*cos(yaw)-dz*sin(yaw)`。因此东海在右适合 `yaw≈0–20°`；南海要到左上，使用 `yaw≈225°`。不能给所有水岸同一个40°朝向。

`H` 是角色脚下实际可走表面高度，包含码头/铺石碰撞面；镜头目标高度为 `H+0.83`。下表 target 是世界坐标，FOV 固定35°，输出1600×900，距离单位米。参考图人物总高没有现实尺度标尺；35°用于当前1.65米角色的首轮画面匹配，仍需看截图中的实际轮廓。

## 验收与“90%”的证据边界

每张图独立记录，不以平均分掩盖关键失败。建议采用100分人工对照表：构图与角色尺度30、岸线/水域方向20、主地标形体与前后关系20、可走平台/台阶10、草石过渡与装饰密度10、光照天气10。此分值是本项目验收工具，不是模型自动计算的客观相似度。

硬条件：角色中心距参考目测中心不超过画宽/高约5%；人物画高进入表列范围或偏差不超过2个百分点；海/溪在正确屏幕侧；主地标不能缺失或被全遮；人物与路、桥、踏石实际接触；无大块绿色方砖、宽纯色裸路、连续无草黑墙；水、草和原角色必须在实际Game渲染中可见。

通过这些条件后再评分；“接近90%”需要十张同机位实景图、具体差距清单和用户对风格的确认。桥能通过、编译无错误、文件capture PASS，都只能证明相应功能项，不能替代这一步。
