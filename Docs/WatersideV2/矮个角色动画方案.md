# ForestSprite 矮比例角色动画方案

核查日期：2026-10-23。范围为只读源码、FBX 二进制骨架、已保存配置和公开一手资料。本轮没有操作 Unity、修改角色或购买资源；下述观感问题区分了源码事实与待运行验证的推断。

建议保留现有 Generic 骨架与披风系统，在 Blender 的原角色上手工制作关键姿势、支撑脚与重心，再烘焙回原骨架。先完成“起步—走路—刹停—转身”这一条短演示，选定风格后扩充生活动作。免费动作库适合提供时间节奏和姿势草稿；比例差异最大的腿部接触、坐姿和头部重心要由人逐姿势调整。继续批量生成正弦摆腿曲线，或只增加混合时长，都不能替代这一步。

**流畅度问题的可归因部分**

`ForestSpriteDemoController.cs:74–76` 用设定速度计算步频，`104–106` 用输入方向选择走跑状态，`168` 将设定速度直接交给 Move。`ActualVelocity` 虽在177行计算，却未用于动画速度。因而顶墙、受坡面阻挡时，脚仍按完整设定速度踏步；按键起停时，根节点速度立刻变化，姿势才开始淡入淡出。前者可产生滑步，后者可产生“身体先移动、脚随后追上”或停止时脚仍在滑动。需要通过一次接触标记测试确认影响量。

166行用540°/s转动整个角色，没有承重脚转步或减速。90°输入转向约0.167秒完成、180°约0.333秒，短腿角色容易像在地面旋转。换走跑时已经保留 normalizedTime，这是应保留的优点；但相同相位仍需对应同一只脚的接触，不能据此认定所有混合已正确。Unity 官方也要求可混合动作的脚接触时刻对齐。[Unity Blend Trees](https://docs.unity3d.com/2022.3/Documentation/Manual/class-BlendTree.html)

205–213行的普通 CrossFade 使用归一化过渡时长，Jump 另用0.04秒固定时长；`.12` 不能直接解读为统一0.12秒。现有 JumpPhase 已区分0.14秒预备、真实上升/下降速度和0.22秒落地，值得保留。新增跳跃应继续由实际离地和触地驱动，避免完整跳跃片段按固定时长播完才落地。

桌面 `轻盈动作重制_20261022/author_airy_actions.py` 和项目 `Source~/retime_walk_loading.py` 表明以前已处理脚底接触、两骨IK、脚趾滚动和重心加载。数值正确能证明脚与地的关系，却无法证明角色节奏、重量与性格得到认可。本次不把旧 PASS 报告或单张截图当作“动画令人满意”的证据。

**动作来源应如何使用**

优先试 **Quaternius Universal Animation Library** 的标准免费档。作者页面注明CC0、可商用、提供带根运动及原地版本；当前页面的Pro为9.99美元起、Source含`.blend`为14.99美元起。整个库120+动作不代表标准免费档含全部，具体候选须检查下载包。可先取坐下、招呼、观察等做重定向试片；不要因为“Universal”就跳过短腿接触修整。版本3.0修正过不同方向动作起脚不同步，说明即使成熟库也需要核对相位。[作者下载页及更新记录](https://quaternius.itch.io/universal-animation-library)

**Mixamo** 可作第二动作来源。Adobe FAQ注明Adobe ID可免费使用，动画可用于商业游戏，同时明确自动绑定针对双足人形，过度变形比例、大型衣物和头发可能失败。我们的角色已有53骨与披风，不应上传整个人物重新自动绑骨；若账户可用，取一段源骨架动作离线重定向即可。FAQ还列出中国国家代码账号的服务限制，不能默认本账户能使用。Mixamo是royalty-free使用许可，不应当成CC0素材包任意再分发。[Adobe官方FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html)

**建议的短动作集**

| 批次 | 动作 | 制作重点 |
|---|---|---|
| 首轮4段 | 起步、舒缓走路循环、刹停、90°原地转身 | 先只做左向/一只脚主导的完整试片；验证后再做另一侧。短腿适度增加步频，但先由支撑脚行程决定速度，不一味拉大步幅。 |
| 移动扩展 | 跑循环、跑停、左/右90°转步、180°回身 | 走跑相位对齐；大转角先减速再换承重脚。180°可由多个转步组成，不先制作8方向全套。 |
| 跳跃 | 蓄力、起跳/上升、下落循环、轻落地；重落地后补 | 保留现有物理落地驱动，重心先压再抬，鞋底落点稳定，头和披风有滞后。 |
| 生活动作 | 坐下、坐姿循环、起身、单手招呼、低头看水/花、抬头看鸟 | 坐姿使用地面或固定座高两个明确场景之一；不承诺一个clip适应任意椅高。手要避开大头、宽披风，镜头中能读出轮廓。 |
| 待机变化 | 呼吸待机、换重心、短暂回望 | 少量随机间隔触发，移动立即退出，避免每帧随机切换。 |

预计首版约16–20段，其中上升/下落可先复用现有Jump分段。观察与招呼可以放一层按Transform路径遮罩的上半身动作，保持腿部移动；转身、跳跃、坐下应是全身动作。Unity支持层遮罩和Override/Additive，但Additive必须有正确参考姿势，首轮上半身Override更容易审查。[Unity Animation Layers](https://docs.unity3d.com/2022.3/Documentation/Manual/AnimationLayers.html)

**实现顺序与验收**

1. 先从当前FBX与 `.blend` 核对绑定和关键姿势，另存候选，不重绑、不改体型。交付8个关键姿势正侧面接触表及10–15秒同机位循环，先确定“轻快但有重量”的节奏。先关闭披风动态看身体，再开启确认两者兼容。
2. 小步改移动驱动：输入保留即时意图，速度经短加减速得到根位移；动画使用经过滤波的实际水平速度、转角和落地状态。低速区用短步，高速区用跑；用小死区和滞回避免状态抖动。先解决起停/顶墙/转弯，再加生活动作。
3. 初版仍由CharacterController负责地形碰撞，动画保持原地；坐下等固定交互用目标位置对齐。脚锁只在接触窗口生效，不能把双脚整个循环锁死，也不能用抬高骨盆掩盖腿长不足。
4. 数值验证建议：同一支撑相脚底累计水平漂移≤2cm、地面穿入≤5mm作为首轮调试目标；每次记录实际速度、脚接触窗口、骨盆高度和转角。坡面、急转和艺术夸张分别记录，不以一个平均值掩盖失败帧。重载prefab后再测，避免仅编辑器预览正确。
5. 观感验收用实际俯视游戏镜头加近景正/侧面，30/60fps各测起停、走跑切换、90/180°转向、顶墙、斜坡、跳起提前碰顶、落地接走、坐下起身。保留正常速度与慢放视频；用户认可首轮4段后再扩充，不用更多clip数量替代风格确认。

本轮可确认的是骨架、动作接线和运动驱动风险，以及适配路径与许可来源。新的动作质量尚未制作或验证；原角色、原场景、用户保存的速度与披风设置均未修改。
